## Quality of the images

[TODO: Resolution, colour depth and quality problems such as faded, cropped or show-through pages.]

Suitability is checked on the image actually supplied to the model, especially for small script and double pages. A nominal DPI value alone confirms no legibility. `IMAGE_DPI` affects only PDF rasterisation and cannot restore missing source detail. The contract allows `page_type: gate_low_resolution` for insufficient images, and the reliability of this model classification needs checking on the corpus.

## Provenance and input roles

[TODO: Record provenance, access, rights, selection and processing for every kind of source.]

Catalogue metadata can come from an existing TEI file while the text is newly produced from images. Both provenance paths are documented separately. An existing transcription can serve as input or as a comparison reference, and its role determines whether an independent recognition comparison is possible.

The manifest takes up object metadata and page order. Field-level provenance and source evidence are documented separately in the project, because the template does not produce them.

## Review sample

A first run with `--sample N` processes the first N transcribable documents, and this selection demonstrates no representativeness. A review sample covers the intended application and names the cases it excludes. The [evaluation reference](../reference/evaluation.md) sets out the requirements.

Taking over a technical method transfers no rights of use to texts, images or catalogue data.
